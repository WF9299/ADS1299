# Monitor HTTP 六通道取源、八通道输出设计

日期：2026-10-23。状态：用户已确认“按推荐方案：仅修改HTTP输出”。目标仓库：`D:/Project/ADS1299_TONG_V2_P`。

## 需求与范围

用户要求在Monitor增加特殊推送模式：只使用CH1–CH6，并可选择其中两个通道的数据代替HTTP输出CH7、CH8。

推荐解释为HTTP取源映射。ADS1299仍采集8路；Monitor本地波形、质量、阻抗、BIAS和正式原始记录保持物理通道含义。特殊模式只在HTTP发送前替换后两列，无需重烧固件。若用户要求ADS硬件停止CH7/CH8采样，则另行扩展固件通道配置及BIAS方案，不以软件复制冒充硬件停采。

## 方案比较

1. **推荐：HTTP输出映射。** 保持现有200点×8列协议，只取物理CH1–CH6并复制两列，兼容现有接收端；本地仍可检查真实CH7/CH8。
2. **固件关闭CH7/CH8并在Monitor补列。** 满足物理停采，但需更新固件、处理通道配置/BIAS与恢复流程，不属于单纯推送功能。
3. **直接发送6列。** 格式更直接，但当前SSVEP明确要求8列，电视端也需确认协议兼容，且不能按用户要求替代CH7/CH8。

## 用户界面与配置

- Monitor“记录”页HTTP区域新增“通道模式”：`原始8通道`（默认）、`特殊：CH1–CH6 + 两路复制`。
- 特殊模式显示两个下拉框：`输出CH7来源`、`输出CH8来源`，范围均为CH1–CH6，默认CH5、CH6；要求选择两个不同来源，如重复则显示明确提示并阻止开始。
- 显示实时映射说明，如`输出CH7 ← CH3；输出CH8 ← CH6；前6路保持原通道`。
- 目的地址预设与通道模式独立；SSVEP、SEU电视及自定义地址均可使用。选择预设不重置通道映射。
- HTTP发送期间锁定模式和来源，停止后修改，再开始时应用新的不可变设置。停止/开始沿用现有清空聚合与发送队列逻辑。
- 映射随HTTP本机配置保存；配置升级读取旧版本时默认原始8通道，保留地址/端口/路径。非法新配置明确报错，不默默使用错误映射。

## 数据处理与接收兼容

原始模式输出保持原状。特殊模式对每个完整200点包生成独立输出数据：

```text
输出 = [物理CH1, CH2, CH3, CH4, CH5, CH6, 物理CHa, 物理CHb]
a、b属于1..6，且a不等于b。
```

时间戳、采样率1000、channels=8、样本数、Marker、设备信息、单位、量程及BIAS实际状态保持原含义；不滤波、不平均、不插值、不原位改动共享record或采集batch。

特殊包增加说明性`channel_map=[1,2,3,4,5,6,a,b]`和`channel_mode`元信息，明确8列只有6路独立来源；真实硬件BIAS掩码不得按输出列重写。旧接收端仍按现有8列字段接收。无法仅凭本地源码保证远端电视接受新增可选字段，提交时说明本地验证范围。

配套SSVEP接收器兼容无映射的旧包（视为1..8），验证并保留映射元信息到原始记录/分析上下文；映射变更时清空已有分析窗，防止不同映射混窗。CCA/FBCCA方法、刺激逻辑和通道选择不改变；复制列不被描述成新增电极或信号增强。
