# USB provisioning and dual transport implementation

- Implemented in the independent C5 project on `codex/usb-provisioning-dual-transport`, version 2.1.0 / STREAM_CONFIG firmware `P300_DUAL_V1`. The approved specification and module plan are in docs/superpowers. Original P4/PCB untouched; no automatic flashing or GitLab push.
- The working local app_config.h is preserved/ignored; legacy network macros are not consumed. Public example contains only acquisition/algorithm/default ports. Successful network settings/Monitor pairing live in the device's p300_network NVS namespace, with candidate validation and rollback. Changed pairing stops old output and returns to serial; duplicate settings avoid needless NVS writes. NVS is not claimed encrypted.
- USB UART0 uses the existing CP2102N/TLP2361 path on GPIO11/12. Management starts before ADS bring-up. Protocol boots at 115200, negotiates 921600/460800, has five-second heartbeat lease, bounded typed CRC32C frames and a single owner. Logs are structured and displayed separately from EEG/export. New stream generations discard queued old UART data; GUI receiver epochs reject stale disconnect/data events.
- Serial mode disables Wi-Fi, supports PC clock anchoring without Internet and all existing controls/Marker. Wi-Fi retains TCP1234/UDP1235 plus HMAC paired Monitor discovery (UDP1236 default, firmware build override and matching Monitor CLI option). Acquisition sample time is preserved; RTT-based mapping does not establish guaranteed 1 ms stimulus accuracy.
- Monitor adds 连接/配网 with USB pairing, network scan/current personal Wi-Fi copy (explicit authorization), mode selection, endpoint roles and campus hotspot assistant. Campus authentication remains on PC; board uses independent hotspot credentials. Required path remains Windows Settings/manual entry/USB submission when WinRT/API permissions or policy prevent automation. Optional PC persistence uses user-scoped DPAPI; failures do not invalidate an otherwise usable USB session. No plaintext credential files or silent firewall/routing changes.
- Mode changes stop current recording/HTTP and require explicitly starting the next segment. JSON device stays seu and raw output semantics remain. Related pre-existing GUI regressions were repaired: two external resistor calibration inputs start unmeasured, verified 1/2-frame send button and readable panel width.
- C5 ESP-IDF6.0.2 builds with official espressif/cjson 1.7.19~2 and PSA HMAC API; dependency lock retained. Host C protocol tests use public header fixture, not private network settings. Nine offline dual-transport tests plus the original 53 PC tests cover framing, controls/Marker, protected storage, GUI endpoint selection and stale-event rejection. Windows network enumeration read-only smoke works; this PC lacks optional WinRT packages, so auto-hotspot control was not exercised.
- Remaining acceptance: flash 2.1.0, choose actual CP210x COM, close IDF monitor, pair via GUI, validate both baud rates/1000 SPS/CRC/sequence, self-test and diagnostics, then actual campus hotspot, IP changes, repeated mode changes and stimulus sync.
