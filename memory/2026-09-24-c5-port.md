# ESP32-C5 firmware port

- Independent project created at `D:\Project\ADS1299_TONG_V2_P\firmware`, based on the current P4 firmware working tree, including its existing uncommitted PC monitor changes. The original P4 project and R8 EPRO were not modified.
- Target is ESP-IDF 6.0.2 / esp32c5 / ESP32-C5-WROOM-1U-N8R8, 8 MB flash and 8 MB PSRAM configured at 40 MHz. Native C5 Wi-Fi STA replaces P4 ESP-Hosted/SDIO; Wi-Fi modem sleep is disabled for stream/marker latency.
- ADS1299 GPIO map: START 0, PWDN 1, SCLK 6, DIN 8, DOUT 9, CS 10, DRDY 23, RESET 24. SPI2, ADS register configuration and PCNT-based DRDY diagnostics are retained. On single-core C5, all tasks use xTaskCreate and acquisition priority 12 outranks TCP/UDP application tasks.
- TCP EEG_BATCH v1, UDP marker/sync, impedance, internal short, BIAS and runtime TX grouping formats are unchanged. The C5 remains a TCP client to the PC monitor on port 1234, control/markers on UDP 1235. Existing Wi-Fi credentials and TCP server IP were carried from the source working tree and must be checked before flashing.
- `idf.py build` completed. Generated image `build/ads1299_c5_p300_firmware.bin` is 1,002,000 bytes, app partition 3 MB with 68% free. esptool image-info reports ESP32-C5, IDF v6.0.2, valid checksum/hash. Scope and host C protocol tests passed.
- PC tool suite: 50 of 53 tests pass; three GUI tests fail because current uncommitted source monitor removed/changed calibration group, runtime TX controls and panel width. Do not interpret those as C5 firmware failures or silently modify the user's prior monitor changes.
- No board flashing or runtime ADC/Wi-Fi validation has been performed. Confirm power, ADS register readback, 1000 SPS DRDY, network and protocol on the actual R8 board; obey RUN/CHARGE and patient safety constraints.
